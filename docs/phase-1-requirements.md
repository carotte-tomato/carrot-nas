# 阶段一 V0.1 详细需求方案：本机 NAS 节点

状态：草案
最后更新：2026-05-09
对应 Roadmap：`roadmap.md` 阶段一

---

## 1. 阶段定位

V0.1 的目标是让一个 NAS 新手，但具备软件开发背景的用户，可以从一台新装 Debian 的普通 x86 主机开始，完成家庭私有云的第一条闭环。

这一阶段不追求“普通人完全无感使用”，也不追求“完整 NAS OS”。它要验证的是：

```text
新装 Debian 主机
  -> 挂载 Windows SMB 共享的 2T 移动硬盘
  -> 安装 Docker 和基础应用
  -> 启动 NAS Agent 和 Web 管理台
  -> 在管理台看到设备、本地磁盘、资源来源和应用状态
  -> 从统一入口打开照片、视频、文件服务
```

阶段一的产品形态是：

```text
本地 Web 管理台 + 本地 NAS Agent
```

同时保留未来接入云端管理台的协议概念，例如设备 ID、注册、心跳和状态上报。

## 2. 已确认需求结论

### 2.1 用户假设

第一阶段用户是软件开发者，但没有 NAS 部署经验。

用户可以接受：

```text
安装 Debian
SSH 登录机器
执行安装脚本
根据提示做选择
复制错误信息进行排查
```

用户不应该被要求理解：

```text
磁盘分区
Linux 挂载
/etc/fstab
Docker Compose 细节
端口映射
应用目录映射
```

### 2.2 安装主路径

V0.1 的主路径是新机器从 0 到 1 初始化。

不以接管已有 NAS 环境为目标，不保证兼容历史 Docker Compose 部署。

### 2.3 管理台形态

V0.1 使用本地管理台优先：

```text
浏览器访问 http://NAS-IP:PORT
```

但 Agent 和管理台之间的概念设计要为未来云端管理台预留：

```text
device_id
register
heartbeat
status_report
app_status
storage_status
```

### 2.4 设备与资源来源策略

V0.1 区分“NAS 服务器设备”和“用户媒体资源来源”。

NAS 服务器设备：

```text
一台专门运行 Debian 的本地服务器
负责运行 Docker、NAS Agent、Web 管理台和基础应用
应用数据库、配置、缓存、缩略图等热数据优先放在服务器本地系统盘 / SSD
```

用户媒体资源来源：

```text
照片、视频、文件等可大量扩展的数据来源
V0.1 验证路径是一块插在 Windows 主机上的 2T 移动硬盘
Windows 将该移动硬盘目录通过 SMB 共享给 Debian NAS 服务器
Debian NAS 服务器将 SMB 共享挂载为本地路径供应用读取
V0.1 默认只读接入，不向该移动硬盘写入新文件
```

主流程是：

```text
保留已有数据
在 Windows 上共享移动硬盘目录
在 Debian NAS 服务器上挂载 SMB 共享
将 SMB 挂载路径登记为媒体资源来源
只读取已有媒体资源，不写入、不移动、不删除
```

直插 USB / SATA 硬盘、Mac SMB 共享、Linux SMB / NFS 共享、其他 NAS 来源，都作为后续资源来源类型预留。

产品长期推荐方向：

```text
媒体盘直接挂到 Debian NAS 服务器
或媒体盘挂到一台专门 Linux 小主机，再通过 SMB / NFS 提供资源
Windows SMB 仅作为 V0.1 的低成本验证方案，不作为长期最优架构
```

### 2.5 一阶段简要概要

V0.1 要做的是一个本地 NAS 控制节点的最小闭环。

简要定义：

```text
在一台新装 Debian 的本地服务器上运行 NAS Agent、Web 管理台和基础 Docker 应用。
Windows 上的 2T 移动硬盘通过 SMB 共享出来，Debian 服务器以只读方式挂载该共享。
Immich、Jellyfin、FileBrowser 默认安装，并读取同一个只读媒体资源来源。
应用数据库、配置、缓存、缩略图和元数据都保存在 Debian 服务器本地系统盘 / SSD。
管理台展示设备状态、本地磁盘容量、媒体资源来源状态、应用状态和应用入口。
```

V0.1 的核心验证问题：

```text
一台普通 Debian 主机能否成为家庭私有云控制节点
已有 2T 媒体资源能否在不迁移、不格式化、不写入的前提下接入
照片、视频、文件能否通过统一入口进入对应开源应用查看
Agent 和管理台能否沉淀出后续云端管理、资源扫描、移动端入口的基础协议
```

V0.1 明确不解决：

```text
手机照片自动备份
向 2T Windows SMB 盘写入文件
自动整理或迁移原始媒体文件
多资源来源聚合
直插硬盘托管初始化
公网远程访问完整体验
普通用户无命令行安装体验
```

### 2.6 Step-by-step 验证流程

阶段一按下面步骤验证：

```text
1. 准备一台 x86 主机，安装 Debian，作为 NAS 服务器。
2. 确认 Debian 服务器可以访问局域网，并可以通过 SSH 登录。
3. 在 Windows 主机上插入 2T 移动硬盘。
4. 在 Windows 上把移动硬盘中的媒体目录通过 SMB 共享出来。
5. 在 Debian 服务器上运行安装入口。
6. 安装器执行前置检查：Debian、权限、网络、DNS、系统盘空间、端口、Docker、SMB 可达性。
7. 用户输入 Windows SMB 地址、共享名、用户名和密码。
8. 安装器安装 cifs-utils，并把 SMB 共享以只读方式挂载到 /data/sources/windows-2t。
9. 安装器验证 SMB 共享可读、容量可读取、挂载参数包含 ro。
10. 安装器创建 /opt/carrot-nas 和 /var/lib/carrot-nas/apps。
11. 安装器安装或检查 Docker / Docker Compose。
12. 安装器部署 NAS Agent、Web 管理台、Immich、Jellyfin、FileBrowser。
13. NAS Agent 采集设备状态、本地磁盘容量、媒体资源来源挂载状态和 Docker 容器状态。
14. 用户打开 http://NAS-IP:PORT 进入本地 Web 管理台。
15. 管理台展示 NAS 在线、媒体资源来源在线、应用运行中和应用入口。
16. 用户从管理台打开 Immich，验证可以查看已有照片和视频。
17. 用户从管理台打开 Jellyfin，验证可以浏览和播放已有视频。
18. 用户从管理台打开 FileBrowser，验证可以浏览和下载已有文件。
19. 用户用手机在同一局域网访问管理台和应用入口。
20. 断开 Windows 共享或关闭 Windows 主机后，管理台应显示媒体资源来源离线，而不是把问题误报为应用异常。
```

### 2.7 实施前还需要确认

下面事项不改变 V0.1 主方向，但会影响第一版实现细节：

```text
1. Debian NAS 服务器形态：旧 PC / 小主机 / 迷你服务器 / 虚拟机。
2. Debian 服务器最低配置：CPU、内存、本地 SSD 容量。
3. Windows SMB 共享目录结构：照片、视频、文件是否已有清晰目录。
4. Web 管理台是否必须设置本地管理员密码。
5. Tailscale 是否默认安装，还是仅保留可选安装入口。
6. 安装器是否需要支持重复执行、修复安装、卸载清理。
```

## 5. 用户旅程

### 5.1 准备机器

用户准备：

```text
一台 x86 主机
一个系统盘，用于安装 Debian
一台 Windows 主机
一块插在 Windows 主机上的 2T 移动硬盘
Windows 上可访问的 SMB 共享目录
稳定的有线或无线局域网
```

用户先完成 Debian 安装，然后进入本项目提供的初始化流程。

### 5.2 执行安装

用户在 Debian 主机上执行安装入口。

安装入口负责：

```text
检查操作系统
检查权限
检查网络
检查本地磁盘和 SMB 资源来源
检查端口
安装 Docker
安装 Docker Compose
部署 NAS Agent
部署 Web 管理台
部署基础应用
生成安装报告
```

### 5.3 接入媒体资源来源

系统引导用户把 Windows SMB 共享接入 Debian NAS 服务器。

对于已有数据的 2T 移动硬盘，主流程是通过 Windows SMB 共享挂载使用，不清空数据，不要求 Debian 直接识别 NTFS / exFAT。

系统应展示：

```text
SMB 服务地址
共享名称
认证方式
挂载路径
共享可用性
读取测试结果
可见容量
可用容量
是否可安全接入
```

系统必须避免要求用户执行分区或格式化操作。

### 5.4 打开管理台

安装完成后，用户在浏览器打开本地管理台。

管理台首页展示：

```text
设备名称
设备在线状态
CPU / 内存
本地磁盘容量
媒体资源来源容量
媒体资源来源挂载状态
应用状态
应用访问入口
基础错误提示
```

### 5.5 使用基础服务

用户可以从管理台进入：

```text
Immich：已有照片和视频查看
Jellyfin：视频库
FileBrowser：文件浏览、下载
```

手机和电脑在同一局域网内可以访问这些入口。

## 6. 功能需求

### 6.1 安装前置检查

系统需要在执行安装前生成检查结果。

检查项包括：

```text
Debian 版本
CPU 架构
sudo / root 权限
网络连通性
DNS 可用性
系统盘空间
SMB 客户端依赖是否存在
Windows SMB 地址是否可达
SMB 共享是否可认证
SMB 共享是否可读
SMB 共享是否按只读方式挂载
关键端口占用
Docker 是否已存在
Docker Compose 是否已存在
```

检查结果分为：

```text
通过
警告
阻塞
```

阻塞项必须停止安装，并给出可读修复建议。

### 6.2 媒体资源来源接入

V0.1 优先支持一个媒体资源来源。

媒体资源来源分阶段支持：

```text
V0.1 验证路径：Windows SMB 共享
后续主路径：USB / SATA 数据盘直插 Debian NAS 服务器
后续扩展路径：Linux SMB / NFS、Mac SMB、其他 NAS 共享、多来源聚合
```

阶段一默认使用 Windows SMB 共享验证资源来源接入能力，但不追求覆盖复杂 Windows 网络共享场景。

Windows SMB 接入要求：

```text
安装 cifs-utils
引导用户填写 Windows 主机地址、共享名、用户名和密码
将 SMB 凭据保存到 root-only 可读的 credentials 文件
创建稳定挂载点，例如 /data/sources/windows-2t
使用 /etc/fstab 或 systemd mount 保证重启后自动挂载
默认以只读方式挂载 SMB 共享，挂载参数需要包含 `ro`
设置 Docker 应用可读取的 uid / gid / file_mode / dir_mode
验证 SMB 连通性
验证读取权限
读取共享容量
登记为媒体资源来源
不移动、不删除用户已有文件
```

V0.1 不要求处理：

```text
Windows 域账号
复杂 ACL 权限
多 Windows 共享
跨网段发现
Windows 睡眠唤醒
SMB 性能调优
Windows 共享自动创建
```

Windows SMB 兼容要求：

```text
Windows 负责本地读写移动硬盘文件系统
Debian 只通过 SMB 访问共享目录
V0.1 默认只读挂载 SMB 共享
如果用户希望写入 SMB 共享，必须明确提示这不属于 V0.1 验收范围
如果 Windows 主机离线或共享不可用，管理台必须显示资源来源离线
应用数据库、配置、缓存、缩略图不放在 SMB 共享上
SMB 共享只承载已有用户媒体资源
```

直插数据盘后续要求：

```text
后续优先支持 USB / SATA 数据盘直接插到 Debian NAS 服务器
直插路径需要识别 NTFS / exFAT / ext4
直插路径默认仍然保留数据挂载
格式化只能作为显式可选操作
```

安全要求：

```text
禁止自动格式化
禁止在 V0.1 Windows SMB 验证路径中要求用户分区
禁止在磁盘识别不明确时继续破坏性操作
禁止把已有数据目录静默迁移或重命名
失败时必须保留可诊断日志
```

### 6.3 基础目录规划

V0.1 区分应用数据目录和媒体资源目录。

应用数据目录建议放在 Debian NAS 服务器本地系统盘 / SSD：

```text
/opt/carrot-nas
/var/lib/carrot-nas
```

媒体资源来源挂载到 `/data/sources`：

```text
/data/sources/windows-2t
```

其中：

```text
/opt/carrot-nas                   保存 Compose 文件、安装配置和运维脚本
/var/lib/carrot-nas/apps          保存应用数据库、配置、缓存、缩略图等热数据
/data/sources/windows-2t          挂载 Windows SMB 共享的媒体资源
```

如果 Windows 共享里已有用户目录，V0.1 不强行整理历史文件，只把该共享作为一个资源来源接入。

V0.1 对 Windows SMB 资源来源的操作范围：

```text
允许：扫描、索引、读取、生成本地缩略图、播放、下载
不做：手机备份写入、网页上传写入、文件删除、文件移动、文件重命名、目录整理
```

### 6.4 Docker 与应用部署

V0.1 使用 Docker Compose 部署基础应用。

默认安装并接入：

```text
Immich
Jellyfin
FileBrowser
NAS Agent
Web 管理台
```

三类应用职责：

```text
Immich：读取只读媒体资源来源中的照片和视频，生成本地索引与缩略图，用于浏览已有照片视频
Jellyfin：读取只读媒体资源来源中的视频目录，生成本地媒体库元数据，用于浏览和播放已有视频
FileBrowser：读取只读媒体资源来源，用于浏览和下载已有文件，不提供对该来源的上传、删除、移动、重命名
```

Tailscale 在阶段一可以作为可选能力，是否纳入默认安装需要继续确认。

应用模板要做到：

```text
目录挂载清晰
端口配置固定或可配置
容器名称可识别
服务可随系统重启
日志可查看
状态可被 Agent 采集
```

### 6.5 NAS Agent

Agent 运行在 NAS 主机上，负责采集本机状态并提供给管理台。

Agent 初版职责：

```text
生成或读取 device_id
提供设备注册信息
提供心跳状态
采集 CPU / 内存基础信息
采集本地磁盘容量和媒体资源来源挂载状态
采集 Docker 容器状态
提供应用访问地址
提供安装和运行错误信息
```

Agent 不负责：

```text
实现文件传输
实现相册功能
实现视频播放
实现复杂权限
执行无确认的破坏性磁盘操作
```

### 6.6 Web 管理台

V0.1 管理台是本地统一入口。

首页至少包含：

```text
设备状态区
本地存储状态区
媒体资源来源状态区
应用状态区
应用入口区
安装检查结果
基础错误提示
```

应用状态至少包括：

```text
未安装
安装中
运行中
已停止
异常
```

应用入口需要展示局域网访问地址。

### 6.7 SMB 验证路径性能与缓存策略

SMB 共享在 V0.1 中只作为验证用媒体资源来源，不作为应用热数据目录。

性能假设：

```text
千兆有线局域网下，SMB 顺序读取通常可以满足照片浏览和多数家庭视频播放
2.5G 有线局域网会明显改善大文件扫描、视频拖动和批量导入体验
Wi-Fi 可用但不作为稳定体验基线
大量小文件扫描会比顺序读取大视频更容易暴露 SMB 延迟
```

缓存策略：

```text
Immich 数据库、缩略图、机器学习缓存放在 Debian NAS 服务器本地 SSD
Jellyfin 元数据、封面、转码缓存放在 Debian NAS 服务器本地 SSD
FileBrowser 配置和数据库放在 Debian NAS 服务器本地 SSD
SMB 共享只放已有原始照片、视频、文件等用户媒体资源
```

体验目标：

```text
照片列表和缩略图浏览不应每次都从 SMB 原图实时生成
首次扫描和首次缩略图生成可以较慢，但完成后浏览应主要命中本地缓存
查看原图、播放原视频、批量导入时才主要受 SMB 和网络速度影响
手机备份写入不走 Windows SMB 资源来源
管理台需要展示资源来源连接状态，避免用户误以为应用本身异常
```

```text
管理台可以展示媒体资源来源容量和挂载状态
管理台可以展示应用运行状态
管理台可以提供应用跳转入口
同一局域网内的电脑和手机可以打开管理台和应用入口
系统不会把手机备份或上传文件写入 Windows SMB 资源来源
系统不会无确认格式化任何磁盘
```

## 8. 风险与待确认问题

### 8.1 已知风险

```text
Windows 主机离线会导致媒体资源来源不可用
SMB 账号、密码、共享权限配置可能失败
SMB 挂载性能依赖局域网质量、Windows 主机性能和移动硬盘性能
SMB 不适合作为应用数据库、缓存、缩略图等热数据目录
Immich / Jellyfin / FileBrowser 对目录权限要求不同
移动硬盘从 Windows 主机断开后，应用状态和挂载状态需要清晰提示
端口可能被占用
Immich 的依赖较多，安装耗时和资源占用较高
```

### 8.2 待确认问题

详见 2.7，当前优先确认：

```text
1. Debian NAS 服务器形态和最低配置
2. Windows SMB 共享目录结构
3. Web 管理台是否必须设置本地管理员密码
4. Tailscale 是否默认安装，还是仅保留可选安装入口
5. 安装器是否需要支持重复执行、修复安装、卸载清理
```
