# V0.1 Prepare：Mac 本机 NAS 服务器熟悉路径

状态：草案
最后更新：2026-05-10
对应阶段：V0.1 准备阶段

---

## 1. 目的

这份文档用于在正式进入 V0.1 之前，先用当前这台 Mac 熟悉 NAS 服务器的核心路径。

当前先不处理外部设备，也不要求准备独立 Debian 主机。目标是在 Mac 本机上跑起一组最小 NAS 服务，理解：

```text
本地目录
  -> Docker 服务
  -> Web 访问入口
  -> 媒体浏览 / 文件浏览
  -> 后续迁移到 Debian NAS 节点
```

这一步不是最终产品形态，而是 V0.1 的 prepare 环节。

---

## 2. 与 V0.1 的关系

正式 V0.1 的目标仍然是：

```text
Debian NAS 服务器
  -> Windows SMB 只读资源来源
  -> Immich / Jellyfin / FileBrowser
  -> NAS Agent
  -> 本地 Web 管理台
```

Mac prepare 阶段先验证更小的一条路径：

```text
Mac 本机
  -> 本地测试媒体目录
  -> Docker Compose
  -> Jellyfin / FileBrowser / Immich
  -> 浏览器访问服务
```

它解决的问题是：

```text
先理解 NAS 服务到底由哪些部分组成
先熟悉 Docker、端口、目录挂载和应用数据目录
先得到一个可以反复试错的本地实验环境
为后续写安装脚本、Compose 模板、Agent 状态采集做准备
```

它不解决的问题是：

```text
不验证真实硬盘托管
不验证 Windows SMB 共享
不验证 Debian 系统安装
不验证 systemd、fstab、cifs-utils
不验证局域网其他设备访问
不作为最终部署架构
```

---

## 3. Mac 本机的角色定义

在这个 prepare 阶段，Mac 同时扮演三种角色：

```text
开发机：编辑代码、写文档、运行命令
测试 NAS：通过 Docker 跑 NAS 类服务
测试资源来源：用本地目录模拟照片、视频、文件资源
```

这和正式 V0.1 的角色关系不同。

正式 V0.1 中，角色应该拆开：

```text
开发机：Mac
NAS 服务器：Debian 主机
资源来源：Windows SMB 共享或后续直插数据盘
```

因此 Mac prepare 阶段的所有路径都要避免写死成最终形态。

---

## 4. 推荐路线

### 4.1 路线 A：Mac 原生文件共享

先用 macOS 自带文件共享理解 SMB、共享目录和权限。

优点：

```text
最简单
不需要 Docker
适合理解 NAS 的文件共享概念
```

缺点：

```text
无法熟悉 Immich / Jellyfin / FileBrowser
无法沉淀 Docker Compose 模板
和 V0.1 工程实现距离较远
```

适合只想理解 NAS 是什么，不适合作为当前项目的主准备路径。

### 4.2 路线 B：Mac Docker 本机 NAS Lab

在 Mac 上安装 Docker 运行时，用 Docker Compose 跑 FileBrowser、Jellyfin，之后再加入 Immich。

优点：

```text
最贴近 V0.1 应用编排
不需要先准备 Debian 主机
可以快速理解端口、卷挂载、应用数据目录
后续 Compose 模板可以迁移到 Debian
```

缺点：

```text
Mac 文件系统和 Linux 有差异
Docker Desktop / OrbStack 的网络行为和 Debian 原生 Docker 不完全一样
不验证真实 Linux 挂载和系统服务管理
```

这是当前推荐路线。

### 4.3 路线 C：Mac 上运行 Debian 虚拟机

用 UTM 或其他虚拟化工具运行 Debian，把虚拟机当作 V0.1 NAS 服务器。

优点：

```text
最接近正式 V0.1
可以验证 Debian、Docker、systemd、目录权限
后续安装脚本可以更早成型
```

缺点：

```text
准备成本更高
需要先理解虚拟机网络、磁盘、SSH
对于当前熟悉阶段有点重
```

适合在路线 B 跑通后进入。

---

## 5. 当前推荐阶段拆分

### P0：准备 Mac NAS Lab

目标：

```text
确认 Mac 可以运行 Docker
创建本地 NAS 实验目录
准备少量照片、视频、普通文件样本
```

建议目录：

```text
~/carrot-nas-lab/
  media/
    photos/
    videos/
    files/
  appdata/
    filebrowser/
    jellyfin/
    immich/
  compose/
```

验收标准：

```text
可以在 Mac 上执行 docker version
可以在本地看到测试媒体目录
可以明确区分 media 和 appdata
```

### P1：先跑 FileBrowser

目标：

```text
用 FileBrowser 浏览 Mac 本地测试目录
理解文件服务的端口、账号、挂载目录
验证只读和可写两种模式的区别
```

为什么先跑 FileBrowser：

```text
它最简单
它最像 NAS 文件入口
它能直接暴露目录挂载是否正确
它能帮助理解应用数据和用户文件不能混在一起
```

验收标准：

```text
浏览器可以打开 FileBrowser
可以看到 media/files 里的测试文件
可以下载文件
知道 FileBrowser 的配置数据放在哪里
```

### P2：再跑 Jellyfin

目标：

```text
用 Jellyfin 读取 media/videos
理解媒体库扫描、元数据、封面、转码缓存
理解原始视频目录和应用缓存目录的区别
```

验收标准：

```text
浏览器可以打开 Jellyfin
可以添加一个视频媒体库
可以播放测试视频
Jellyfin 的配置和缓存保存在 appdata/jellyfin
```

### P3：最后跑 Immich

目标：

```text
理解 Immich 的服务组成更多，不适合作为第一个服务
验证照片 / 视频导入、缩略图、本地数据库和对象存储目录
为后续 V0.1 判断 Immich 的部署复杂度
```

验收标准：

```text
浏览器可以打开 Immich
可以导入少量测试照片
可以看到缩略图
知道 Immich 相比 FileBrowser / Jellyfin 多了哪些依赖
```

### P4：沉淀 Compose 模板雏形

目标：

```text
把 FileBrowser、Jellyfin、Immich 的本地运行方式整理成可读 Compose
把端口、目录、应用数据路径抽成变量
为正式 Debian 部署保留替换空间
```

需要注意：

```text
Mac 路径不能直接作为 Debian 路径
Mac Docker 的网络模式不能直接当成 Debian 结论
Compose 文件要区分 lab 版本和 production 版本
```

验收标准：

```text
可以一条命令启动本地 NAS Lab
可以一条命令停止本地 NAS Lab
可以清楚说明每个 volume 的用途
```

### P5：进入 Debian VM 预演

目标：

```text
在 Mac 上创建 Debian 虚拟机
把 P1-P4 的经验迁移到 Linux 环境
验证真正的 Linux 路径、权限、Docker、systemd
```

验收标准：

```text
Debian VM 可以 SSH 登录
Debian VM 可以运行 Docker Compose
同一套服务可以在 Debian VM 上启动
目录规划开始接近 /opt/carrot-nas、/var/lib/carrot-nas、/data/sources
```

---

## 6. 第一阶段最小闭环

Mac prepare 的第一个最小闭环建议只包含：

```text
Docker 运行时
本地测试目录
FileBrowser
Jellyfin
```

暂时不把 Immich 放进第一个闭环，因为 Immich 依赖更多，容易把学习重点从 NAS 基础概念带偏。

第一阶段完成后，应该能回答：

```text
什么是应用数据目录
什么是媒体资源目录
什么是容器端口
什么是目录挂载
为什么用户原始文件不能和应用数据库混在一起
为什么 V0.1 要区分 /var/lib/carrot-nas/apps 和 /data/sources
```

---

## 7. 后续与正式 V0.1 的映射

| Mac prepare | 正式 V0.1 |
| --- | --- |
| `~/carrot-nas-lab/media` | `/data/sources/windows-2t` |
| `~/carrot-nas-lab/appdata` | `/var/lib/carrot-nas/apps` |
| `~/carrot-nas-lab/compose` | `/opt/carrot-nas` |
| Docker Desktop / OrbStack | Debian Docker Engine |
| 本地测试文件 | Windows SMB 只读资源来源 |
| 手动打开应用入口 | Web 管理台统一入口 |
| 手动检查容器状态 | NAS Agent 采集状态 |

---

## 8. 进入正式实现前的完成条件

完成 Mac prepare 后，再进入正式 V0.1 会更稳。

建议满足这些条件：

```text
Mac 上能启动 FileBrowser 和 Jellyfin
理解 media 和 appdata 的边界
理解 Compose 中 ports、volumes、environment 的含义
知道哪些经验可以迁移到 Debian，哪些不可以
已经决定是否把 Immich 纳入第一版默认安装
已经决定本地管理台第一版只展示状态，还是也负责安装动作
```

---

## 9. 下一步建议

下一步不要直接写 Agent，也不要直接做 Web 管理台。

建议先做：

```text
1. 修复或更新 Mac 上的包管理环境。
2. 安装一个 Docker 运行时。
3. 创建 ~/carrot-nas-lab 目录。
4. 放入少量测试照片、视频和普通文件。
5. 用 Compose 跑起 FileBrowser。
6. 再加入 Jellyfin。
```

当 FileBrowser 和 Jellyfin 都能在 Mac 本机跑起来后，再决定是否继续加入 Immich，或者先转入 Debian VM 预演。
